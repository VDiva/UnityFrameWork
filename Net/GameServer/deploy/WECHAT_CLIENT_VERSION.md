# 微信小游戏服务器兼容版本校验

## 配置与发布

- 客户端自身/资源版本是 `Assets/FrameWork/Resources/ConfigData.asset` 的 `versions`（当前为 `1009`），只用于客户端自身和 CDN 资源目录，不参与服务器兼容校验。
- 客户端 `serverVersion`（当前为 `100`）表示该客户端包兼容的服务器版本，随包发布，不能用服务器返回值覆盖它。
- 服务端版本设置在 `GameServer/appsettings.json` 的 `WeChatMiniGame:ServerVersion`（当前为 `100`）。也可使用 ASP.NET Core 环境变量 `WeChatMiniGame__ServerVersion`；环境变量修改后需重启服务。仅未配置新字段时回退旧字段 `WeChatMiniGame:ClientVersion`，新字段存在但为空时不回退。已有部署使用旧环境变量的，应迁移至新变量。
- 版本校验只走现有 WebSocket 的二进制 Protobuf 请求/响应，不使用 HTTP/HTTPS 请求。仅使用现有 socket 合法域名；不需要为版本校验配置 request 合法域名。
- 已移除 `/client-version` HTTP 路由。客户端和服务器都需要重新构建发布：旧服务器不支持此查询，新客户端会提示未返回版本或超时；仍使用旧 HTTPS 校验逻辑的客户端也需要更新，请协调切换。
- 仅更新客户端功能/资源时，可以修改 `versions` 而保持 `serverVersion` 不变，服务器无需修改。也可以先升级客户端 `serverVersion`，高于服务端要求时仍放行。服务端 `ServerVersion` 表示最低兼容版本；提高它之前应先发布对应微信新包，低于该要求的旧包会被要求更新。此规则需要保证新版客户端兼容较旧服务端。
- 首次发布之前的旧客户端没有独立服务器版本字段，仍按旧逻辑执行，必须更新到带新逻辑的客户端后才能解耦。

## 行为

LoadScene 负责启动顺序：先建立 WebSocket 连接并等待成功，再查询版本，通过后准备登录凭证、获取区服列表并进入 StartScene。检测方法仅查询和比较版本，不调用 Connect，不等待建立连接；未连接时返回明确错误。启动检测失败后由 LoadScene 在玩家选择重试时恢复连接。玩家在 StartScene 点击登录时先查询版本，再获取新的微信 code，实际发送登录前再次检查。每次查询读取服务端当前配置，不缓存旧连接上的校验结果。只比较客户端 `serverVersion` 和服务端 `ServerVersion`，按非负整数比较：客户端大于或等于服务端要求时放行，小于时更新。允许两端空白和前导零；空值、负数、小数、非数字或超过 Int64 上限的配置会报错，不放行也不误触发更新。客户端资源字段 `versions` 不参与比较；编辑器及非微信客户端不自动调用微信版本检查。

协议复用 `Msg`，无需重新生成 protobuf：查询为 `GetServerList` 附带 `DataDic["__server_version_query"]="1"` 和原有 `__web_request_id`。服务端优先识别该标记并直接返回版本，不访问数据库、不执行登录；普通区服列表请求保持不变。响应包含 `__server_version_query`、`__server_version` 和匹配的 `__web_response`。客户端只完成关联请求，不把版本响应广播成 Tips 或房间事件。缺失配置返回明确错误，查询超时或连接变化时不允许登录。

已登录或已提交登录的连接断开后继续自动尝试恢复网络连接，但恢复后只返回 StartScene，不自动登录、不直接进入大厅。清空旧登录会话及房间状态，作废旧场景加载的进入回调，等待玩家重新点击登录。前后台切换导致的重连也遵循这一流程；首次启动尚未登录时的网络重试仍继续加载服务器列表。

客户端版本大于或等于服务端要求则继续。小于时停止登录、关闭连接并取消自动重连，只在微信 SDK 发出 `OnUpdateReady` 后调用 `ApplyUpdate` 自动重启。若新包早已准备好，检测到客户端版本过低时立即应用。

服务器不能直接提供或指定微信代码包，也不能保证微信后台立即提供新版本。没有新包、下载失败或迟迟未就绪时不反复重启，提示关闭并重新打开小游戏。启动时请求失败可在弹窗里重新检测；登录阶段失败会显示原生提示并不发送登录。已经在线的对局不定时轮询版本，下次玩家主动登录时重新检查。

本功能是客户端更新入口，不是防篡改协议或服务端强制准入校验。

## 验证清单

1. 未登录的 WebSocket 连接可查询版本，响应请求 ID 匹配；无任何 `/client-version` HTTP 请求。
2. 客户端 `serverVersion` 和服务端 `ServerVersion` 均为 `100` 时启动和登录正常，即使客户端 `versions` 为 `1009` 也不受影响；断网时不越过校验，恢复网络后可重新检测。
3. 客户端 `serverVersion=101`、服务端 `ServerVersion=100` 时允许登录；客户端 `99`、服务端 `100` 时提示更新。确认按数字而不是字符串顺序比较。
4. 微信开发者工具模拟更新：分别测试“客户端版本过低后下载完成”和“下载先完成后检测到客户端版本过低”，均只应用一次更新。
5. 模拟下载失败、无新包、服务端版本配置为空、查询超时、旧服务器返回非版本响应，确认不登录、不循环重启。
6. 大厅/战斗中重启服务器，恢复连接后必须停在 StartScene，未点击登录不得发送 Login 或进入大厅；点击后检查版本并使用新的微信 code。只有客户端版本低于服务端要求时才提示更新并阻止进入大厅。
7. 使用正式发布包真机验证完整更新链路；仅编译通过不能替代微信环境验证。
8. 大厅/地图加载中断线、后台恢复、连续断线、登录按钮连点、获取 code 时断线：旧加载不能再次派发进入事件，旧登录任务不能在新连接上发送登录。

自动化检查：`dotnet run --project Net/GameServer/Tests/ServerVersionChecks/ServerVersionChecks.csproj`。测试使用内存 WebSocket 替身走真实 PlayerSession 接收、查询分发、发送队列和 Protobuf 编解码，不连接生产环境或数据库。
